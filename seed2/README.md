# Каталог тестов

Шесть методик в формате для загрузки в схему `schema.sql`. Первые три описаны ниже, тесты 4–6 в последнем разделе «Продолжение: второй пакет». Состав таблиц тот же, что в спецификации. `attempts` стоит раньше `user_test_progress`: в документе порядок обратный, и скрипт падает на внешнем ключе.

Команды ниже запускать из папки `seed/`.

## JSON-файлы

Каталогов два, формат у них одинаковый (`catalog.schema.json`).

| Файл | Сколько тестов | Какие | Когда брать |
|---|---|---|---|
| `catalog.json` | 6 | `SJO`, `REAN_BADMAEV`, `POAK`, `KASS_COMM`, `NEED_COGNITION`, `CRIT_THINKING` | база создаётся с нуля или загружается всё сразу |
| `catalog_batch2.json` | 3 | `KASS_COMM`, `NEED_COGNITION`, `CRIT_THINKING` | первые три теста уже загружены, нужен только второй пакет |

`catalog_batch2.json` это точная копия последних трёх тестов из `catalog.json`. Первые три теста (`SJO`, `REAN_BADMAEV`, `POAK`) в `catalog.json` не менялись. Версия теста, которая уже есть в базе, при загрузке пропускается, поэтому порядок и повторная загрузка ошибок не дают.

Остальные JSON-файлы не относятся к каталогу:

| Файл | Что это |
|---|---|
| `example_packs.json` | пример ответов респондентов, 12 пачек, все шесть тестов |
| `example_packs_batch2.json` | то же только для тестов 4–6, 6 пачек |
| `example_expert_scores.json` | пример оценок методиста за открытые ответы (только `CRIT_THINKING`) |

Формат ответов и оценок проверяют `response_pack.schema.json` и `expert_scores.schema.json`.

## Тесты

| Код | Методика | Вопросов | Шкалы |
|---|---|---|---|
| `SJO` | СЖО, Леонтьев | 20 | 6, сумма |
| `REAN_BADMAEV` | Мотивация учебной деятельности, Реан, Бадмаев | 34 | 7, среднее |
| `POAK` | ПОАК | 12 | 4, сумма |

Коды вопросов: `SJO_q01` … `SJO_q20`, `REAN_q01` … `REAN_q34`, `POAK_q01` … `POAK_q12`. В бланках таких кодов нет, номер в коде совпадает с номером пункта. Версия у каждого теста `1`, опубликована. Тип всех вопросов `scale`.

## Значения ответов

Сначала ищется `raw_value`, потом текст варианта без учёта регистра.

СЖО, слева направо по бланку 3-2-1-0-1-2-3:

| `raw_value` | текст |
|---|---|
| `LEFT_3` | Левое, 3 |
| `LEFT_2` | Левое, 2 |
| `LEFT_1` | Левое, 1 |
| `BOTH` | Оба равны (0) |
| `RIGHT_1` | Правое, 1 |
| `RIGHT_2` | Правое, 2 |
| `RIGHT_3` | Правое, 3 |

В тексте вопроса оба полюса: `ЛЕВОЕ: … || ПРАВОЕ: …`.

Реан–Бадмаев: `1` … `5`.

ПОАК: балл `0` … `4` или слова «никогда», «редко», «иногда», «часто», «всегда». «Никогда» это `0`. Если в выгрузке «никогда» придёт как `1`, оно совпадёт с «редко».

## Пачка ответов

Файл импорта — массив объектов.

```json
{
  "respondent": "r0001",
  "test_code": "POAK",
  "version": 1,
  "submitted_at": "2026-09-01T10:00:00Z",
  "source": "form",
  "answers": [
    {"question_code": "POAK_q01", "value": "2"}
  ]
}
```

`respondent` становится `users.login`. `version` можно не указывать, тогда берётся последняя опубликованная. `submitted_at` можно не указывать, тогда ставится время импорта. `source` в базу не пишется.

Пачка принимается целиком или отклоняется целиком. Респондента загрузчик создаёт сам: роль `student`, пароль `!`, войти под ним нельзя. Повтор с тем же `submitted_at` пропускается. Без `submitted_at` повтор создаст вторую попытку.

## Загрузка

Порядок шагов всегда один: каталог, ответы, оценки методиста (только для `CRIT_THINKING`), расчёт шкал.

База с нуля, все шесть тестов:

```bash
createdb tests
psql -v ON_ERROR_STOP=1 tests -f schema.sql
pip install -r requirements.txt
python3 load.py catalog catalog.json
python3 load.py packs example_packs.json
python3 load.py expert example_expert_scores.json
python3 load.py scores
```

Первые три теста уже загружены, добавляется второй пакет:

```bash
python3 load.py catalog catalog_batch2.json
python3 load.py packs example_packs_batch2.json
python3 load.py expert example_expert_scores.json
python3 load.py scores
```

Подключение: `DATABASE_URL`, по умолчанию `dbname=tests`.

Если версия теста уже есть, загрузчик её не перезаписывает. Изменение ключа — это `version_no` 2.

Сборка каталогов заново: `python3 build_catalog.py [папка_с_docx]`, за один запуск создаются `catalog.json` и `catalog_batch2.json`. Без аргумента docx ищутся на уровень выше `seed/`. Исходные docx в репозиторий не входят, готовые каталоги лежат рядом.

## Продолжение: второй пакет (тесты 4–6)

Этот раздел относится только к трём тестам: `KASS_COMM`, `NEED_COGNITION`, `CRIT_THINKING`. Всё выше про первые три теста не менялось. Формат каталога и пачки ответов тот же, схема таблиц не менялась.

Каталог на эти три теста это `catalog_batch2.json`. Те же тесты входят и в `catalog.json`, где всего шесть (подробнее в разделе «JSON-файлы» вверху). Загружать достаточно одного из файлов.

| Код | Методика | Вопросов | Тип вопроса | Шкалы |
|---|---|---|---|---|
| `KASS_COMM` | Стили коммуникации, П. Касс | 10 | `single_choice`, 2 варианта | 4, сумма |
| `NEED_COGNITION` | Шкала потребности в познании | 18 | `scale`, 7 вариантов | 1, сумма |
| `CRIT_THINKING` | Критическое мышление, Д. Кинчер | 15 | `open_text` | 6 категорий и итог |

Коды вопросов: `KASS_q01` … `KASS_q10`, `NFC_q01` … `NFC_q18`, `CT_q01` … `CT_q15`. Версия `1`, опубликована.

### Касс

В каждой паре выбирается одно утверждение. Буквы бланка в `raw_value` записаны латиницей по порядку: А → `A`, Б → `B`, В → `C`, Г → `D`. Загрузчик принимает и кириллические А, Б, В, Г. Латинскую `B` из внешней выгрузки он понимает как `B` (то есть Б), хотя по виду она может означать кириллическую «В». Это нужно сверить по реальной выгрузке формы.

| Пара | Буквы | Пара | Буквы |
|---|---|---|---|
| 1 | A, B | 6 | B, D |
| 2 | C, D | 7 | A, D |
| 3 | A, C | 8 | B, C |
| 4 | B, D | 9 | A, B |
| 5 | A, C | 10 | C, D |

Выбранный вариант даёт 1 балл в шкалу своей буквы.

| Шкала | Буква | Стиль |
|---|---|---|
| `ACTION` | A | Действие |
| `PEOPLE` | B | Люди |
| `PROCESS` | C | Процесс |
| `IDEAS` | D | Идеи |

Каждая шкала 0–5, сумма четырёх всегда 10. Стиль, который ни разу не выбран, получает 0. В `interpretation` записано правило из документа: от 4 баллов и выше доминирующий стиль.

### Потребность в познании

Ответ `1` … `7` по шкале согласия: `7` абсолютно согласен … `1` абсолютно не согласен. Цифра в выгрузке равна цифре на бланке. Обратные пункты: 3, 4, 5, 7, 8, 9, 12, 16, 17, балл у них `8 − ответ`. У остальных балл равен ответу. Одна шкала `TOTAL`, сумма по 18 пунктам, от 18 до 126. Порогов интерпретации в документе нет.

### Критическое мышление

Все 15 вопросов `open_text`. Ответ и обоснование пишутся одним текстом через разделитель:

```
ОТВЕТ: Нет || ОБОСНОВАНИЕ: в задаче указаны две причины, а в выводе учтена одна
```

В пачке это значение `value`, в базе оно попадает в `attempt_answers.answer_text`, вариант не выбирается. Пустой ответ на обязательный вопрос считается пропуском.

Эталон хранится как единственный вариант вопроса: `is_correct = true`, `raw_value` пустой, в тексте ключ и максимум баллов за задание. Выбрать такой вариант нельзя, он нужен для подсказки при проверке.

Категории проверяются методистом вручную:

| Шкала | Задания | Максимум |
|---|---|---|
| `INFERENCE` | 2–4 | 9 |
| `SEQUENCE` | 5–6 | 11 |
| `CAUSES` | 1, 7, 8 | 8 |
| `TEXTS` | 9–12 | 12 |
| `TERMS` | 13–14 | 5 |
| `RELEVANCE` | 15 | 1 |
| `TOTAL` | сумма шести категорий | 46 |

`TOTAL` составная шкала: в `scale_dependencies` шесть строк с коэффициентом 1 и операцией `+`. Категории не пересекаются, поэтому сумма корректна. В `interpretation` категорий записаны уровни из документа (сформирована, частично сформирована, не сформирована). Числовых порогов в документе нет.

Баллы ставит методист (`users` с ролью `methodist`, по спецификации форма `/methodist/manual-check`). Одна строка оценки это один ответ и одна шкала категории задания:

```json
{"respondent": "r0001", "test_code": "CRIT_THINKING", "submitted_at": "2026-09-01T10:00:00Z",
 "question_code": "CT_q01", "scale_code": "CAUSES", "expert": "alisova.a", "score": 3}
```

Поля `version` и `submitted_at` как в пачке ответов. Строка пишется в `manual_answer_scores`. Балл не может быть больше максимума шкалы. Максимум за отдельное задание указан в тексте эталона, загрузчик его не проверяет. Если на один ответ поставили несколько оценок, берётся среднее.

### Загрузка

```bash
python3 load.py catalog catalog_batch2.json
python3 load.py packs example_packs_batch2.json
python3 load.py expert example_expert_scores.json
python3 load.py scores
```

`scores` нужно запускать после проверки всех заданий: категория считается по тем ответам, которые уже оценены, а `TOTAL` появляется, когда есть все шесть категорий.

### Что изменилось в `load.py`

- Ответы `open_text` пишутся в `answer_text`.
- Команда `expert` загружает оценки методиста.
- Составные шкалы считаются при операциях `+` и `-`. Операции `*` и `/` не поддержаны, в каталоге их нет.
- Шкала типа `sum`, по которой в попытке нет ни одного выбранного варианта, получает 0 (раньше строка не создавалась). Результаты первых трёх тестов от этого не менялись.
